# 用 Markdown 写简历，难的不是语法，是纸张和导出——Resume Craft v2.1.0 实践

> 草稿，未发布。基于 marketing/drafts/main.md 重写，偏开发者技术实践。

GitHub：https://github.com/kunlong-luo/resume-craft
在线体验：https://kunlong-luo.github.io/resume-craft/

## 为什么又做一个简历工具

开发者写简历的痛点很具体，不是缺模板，而是：

1. Word 里调对齐、分页、字体要花很久，换台电脑就变样；
2. 内容多两行，变成难看的“1.1 页”；
3. 投海外岗位时，搞不清 A4 还是 US Letter，日期写 `2026.09` 还是 `Sep 2026`；
4. 网上简历工具要注册、要上传，简历这种敏感文件不想走服务器。

Resume Craft v2.1.0 的思路是：编辑留在本地，用 Markdown 做源，用浏览器做排版和导出。开源 MIT，无需注册，打开就能写。

## 技术设计上怎么取舍

**Markdown ↔ 表单双向同步，而不是二选一**

编辑区可以在结构化表单、Markdown 源码和板块排序之间切换，旁边的简历画布实时更新。拖拽可以重排经历和技能顺序，二级标题板块也能整体平移。这样既保留 Markdown 的可控性，也让不熟悉 Markdown 的人能用表单编辑。

**纸张是基准，不是样式**

预览、打印、导出都围绕当前 A4 / US Letter 设置，按纸张尺寸做视口缩放并显示分页边界。v2.1.0 新增 Target Market：美国、加拿大、英国、爱尔兰、中国、International。还在用默认值时，会按市场推荐纸张和日期格式，但随时可以手动覆盖。日期支持 `2026.09`、`Sep 2026`、`September 2026` 等。

超页可以先用“一键压缩贴合”处理：微调页边距、行高、段落间距，尝试把轻微溢出收回一页，而不是先手调每个段落。

**字体用系统栈，接受轻微差异**

用 PingFang SC、Microsoft YaHei、Source Han Sans 等系统降级链，不加载第三方字体 CDN。深色模式下纸张保持白底黑字隔离。诚实地说：不同系统浏览器的字体度量仍有轻微差别，重要投递以最终 PDF 为准。

**ATS 检查只做诚实的事**

前端完成两类检查：粘贴 JD 对比关键词缺口；扫描联系方式遗漏、时间重叠、`react` -> `React` 这类大小写。这只是可读性和匹配度参考，不承诺 ATS 通过。

PDF 导入也是本地的：带文本层的 PDF 用 PDF.js 在浏览器提取，不上传。导入前会显示提取质量、邮箱电话和章节识别情况。扫描件/纯图片暂不做 OCR，加密或无文本层的 PDF 会提示改用文本粘贴。

**导出分两条路，别用错**

- ATS PDF（推荐）：点顶部按钮或 Ctrl/Cmd+P，浏览器“另存为 PDF”。保留可选文本，适合投递。纸张选 A4/Letter，边距先试“无”，去掉页眉页脚，需要背景再勾背景图形。
- 快速 PDF（备用）：html2canvas + jsPDF 光栅化，适合快速分享。因为是图片，不适合 ATS 投递。

**分享和存储的边界**

草稿和设置主要在浏览器 localStorage，非加密，别当保险箱。注意：项目没有保存简历的后端。

分享链接载荷放在 URL fragment，不进查询参数。公开链接就是持有可读，只发可信人。密码保护链接是本地 AES-256-GCM 加密后生成，密码不进链接，密码和链接分开发。

## 怎么试

1. 打开在线体验，粘贴一段旧简历或导入 PDF 试试提取质量；
2. 切一下 Target Market，看纸张和日期推荐是否符合预期；
3. 跑一次 ATS 检查，再用 ATS PDF 导出对比预览是否一致。
