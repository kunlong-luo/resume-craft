## 正文草稿

如果你平时习惯用 Markdown 写文档、写博客，写简历时可能遇到过这些情况：

Word 里调对齐和分页比较花时间；简历多出一两行变成“1.1 页”；换一台电脑打开，字体和换行又变了；想投海外岗位时，不确定该用 A4 还是 US Letter，日期该写 `2026.09` 还是 `Sep 2026`。

Resume Craft v2.1.0 想解决的是这个具体流程：用你熟悉的方式写简历，所见即所得地控制纸张和导出结果。

它的工作方式是这样的：

**1. Markdown 和表单是同步的**

编辑区可以在结构化表单、Markdown 源码和板块排序之间切换，旁边是实时简历预览。改姓名职位，或者直接改项目经历的 Markdown，状态和预览会同步更新。你也可以拖拽调整经历和技能板块的顺序，不用剪切粘贴整段文字。系统还能识别二级标题做板块排序。

**2. 本地优先，无需注册**

编辑中的简历和设置主要保存在浏览器 `localStorage` 中，项目本身不提供用于保存简历内容的应用后端。打开页面就能写，不用建账号。需要说明的是：`localStorage` 本身并非加密存储，请把浏览器账户、设备和本地备份视为敏感环境。

PWA 支持安装到桌面和移动端，离线也能打开编辑。字体使用本机系统字体栈（PingFang SC、Microsoft YaHei、Source Han Sans 等），不从第三方字体 CDN 加载，以减少跨设备差异。不同系统和浏览器的字体度量仍可能有轻微变化，重要投递建议以最终导出的 PDF 为准。

**3. A4 / US Letter + Target Market**

v2.1.0 增加了 Target Market：美国、加拿大、英国、爱尔兰、中国和 International。

当你还用默认值时，它会按目标市场联动推荐纸张和日期格式；你也可以随时手动覆盖。纸张支持 A4 和 US Letter，预览、打印和 ATS 导出会按当前设置显示对应分页边界。日期支持 `2026.09`、`Sep 2026`、`September 2026` 等样式，模板和诊断提示有中英双语。

顶栏还有“一键压缩贴合”：当内容轻微溢出到第二页时，会自动微调页边距、行高和段落间距，尝试把内容收回一页，减少常见的超页问题。

**4. ATS 检查是辅助参考，不保证通过**

这里需要说清楚：它不承诺 ATS 一定通过。

它提供的是两类前端完成的检查：

- 粘贴目标岗位 JD，对比关键词匹配度，提示核心技能短板；
- 扫描联系方式遗漏、经历时间重叠、技术词汇大小写（例如 `react` 提示为 `React`、`Node.js`）等问题。

PDF 导入也是本地完成的：带文本层的 PDF 用 PDF.js 在浏览器本地提取文字，文件不会上传。导入前会展示文本提取质量、邮箱/电话和常见章节识别情况，作为机器可读性的参考。扫描件/纯图片 PDF 暂不做 OCR，带密码或缺少文本层的 PDF 会提示改用文本粘贴。

**5. 两条 PDF 导出路径**

- **ATS PDF（默认、推荐）**：点顶部“ATS PDF”，或用 Ctrl/Cmd + P 调起浏览器打印，选择“另存为 PDF”。这种方式在支持的情况下保留可搜索、可选择的文本，更适合正式投递。
- **快速 PDF（备用）**：用 `html2canvas-pro + jsPDF` 把画布渲染成图片型 PDF，适合快速下载或打印受限时使用。因为内容被光栅化，不建议作为 ATS 投递的首选。

打印时按当前简历设置选 A4 或 Letter，边距优先尝试“无”，需要保留主题背景时勾选“背景图形”，建议取消页眉页脚。

**6. 分享链接的安全边界**

需要分享时有两种链接：

- 公开分享把可读取的载荷放在 URL fragment 中（不会作为查询参数发给托管站点），应视为“持有链接即可读取”，只发给可信接收者；
- 密码保护分享会在浏览器本地用密码派生密钥做 AES-256-GCM 加密后再生成链接，密码本身不写入链接。仍依赖密码强度和安全传递，建议把密码和链接分开发送。

**7. 开源、无需注册**

项目采用 MIT License 开源。正常编辑不需要账号。反馈在 GitHub Discussions，安全问题按 SECURITY.md 私密报告，不要在 Issue 里贴真实简历、令牌或密码。
